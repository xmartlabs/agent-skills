# Tribunal releases

One row per freeze of the tribunal plugin, appended by `plugins/tribunal/release.sh`
(through `rust/scripts/release.mjs --record`). A row asserts one thing: **the offline gate
was green at that content hash.** It is not a quality claim, and no single run can
support one: candidate generation reproduces at only 14 to 16 percent between
identical runs.

**Numbering.** Tribunal was developed in a private repository before it moved
here. Rows 99 to 110 were frozen there: their tags, commits and `#N` pull request
numbers belong to that repository and do not exist in this one, and they are kept
as a changelog only. This repository starts at a snapshot of tribunal 110, and its
first freeze is 111. Rows before 99 are not included. From 115 on, a freeze is a semver version
(`tribunal/v115.1.0`) and pins the binary tagged with the same version when it
ships a new one; `docs/maintaining.md`, "Versions", has the rule.

**The Gate cell says which gate ran.**

- `N/N full`: every check ran, the client-name scan included, against the test-data
  directory (`TRIBUNAL_HARNESS_DATA`), which is not part of this repository.
- `N/N portable (client-name scan not run)`: no test-data directory was available.
  This is a weaker claim and `release.sh` only records it when asked with `--portable`.
- Rows up to v112 name the Workflow's replay battery (`pr-battery-`), and their
  `portable` rows skipped the replays that needed the data; rows from v113 name the
  Rust battery (`rust-battery-`).

Notes are written in generic terms. Nothing that identifies a client's repo, PR or
cost belongs in a row.

## Known open

- **Persist relay.** The agent that copies the metrics row in parts can drop a member
  whose value is `null`, `[]` or `0`. Since 98 a refused part is rewritten up to three
  times. Whether that raises the share of rows written has not been measured live.
- **Two rows landing together** was shown with 12 concurrent writers offline and has not
  been observed live.
- **No start time.** When a run has no `startEpoch`, the row check looks only at the
  last row, so two runs finishing together can still confuse each other for that run.
- **Review quality outside the tested stack.** It was measured on a Node, Express and
  Prisma backend and a React frontend only.
